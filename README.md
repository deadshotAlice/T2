### 1
|面板|作用|
|:---:|:---:|
|元素（Elements）|对于简单程序，可查到网页html源代码（如果你有耐心全点开）；对于用JS操作过的程序，则是执行JS代码后的结果。|
|控制台(Console)|查看JS代码报错，JS数组，console等输出结果，查看网络403与404报错等|
|源代码(Sources)|查看源代码，同时可以临时修改代码（刷新丢失），用于调试，真正的原始代码|
|网络(Network)|搭建api，服务器等，可查看状态：200，403，404；在控制台也能收到报错|
|性能(Performance)|可显示LCP、CLS、INP，帧率等数据，分析页面响应速度与视频等问题。|

### 3
Cookie:浏览器保存在本地的一段文本数据，用于让服务器识别会话者。
<br>
（ds解释：Cookie 解决的是“HTTP 记不住人”的问题，让服务器能在多次请求间识别同一个浏览器会话；代价是带来隐私、安全和请求开销问题。）
<br>
（Microsoft 的“了解详细信息”：HTTP Cookie 用于管理用户会话、存储用户个性化首选项以及跟踪用户行为。 使用应用程序工具的“Cookie”窗格可以查看、编辑和删除网页的 HTTP Cookie。）
<br>

获取：最完整的去应用程序下面的cookie查。也可以Console界面输入document.cookie去找（这样只能找到一个）；或者去Network点一条，到标头里找，但可能会只有“显示标头”，比如ds问答界面，b站的有一部分是完整的，能找到cookie（还是那一个）。
<br>
有趣片段：用document或Network查的，只能查到一个，在B站哪都一样，应用于标识网站浏览器（ds说是标记浏览器，但是ds和B站的这个cookie不一样）。其它的不好猜。有一种叫“转到第三方Cookie”，这种东西应该也是标识浏览器的。

### 4
GET多（这个还得看详情，一堆的fetch类型），网络的GET是收东西，POST是发东西。
<br>
200表示“服务器正常接受请求”
<br>
404表示“服务器找不到这个资源”
<br>
403表示“服务器找到了却不给发”，例如没权限，或者是手速太快给刷爆了（当时我疑惑了很久）。
<br>
304：“资源没变化，本地缓存”
<br>
没有找到200与非200的Content-type的明显区别。它告诉我们浏览器的响应类型（text/event-stream 或 application）,响应结果（javascript：可执行脚本  json：数据），以及编码类型（charset=utf-8）
